# NecrotixLab 1.3.97

Booking 1.4.0 now schedules appointments inside NecrotixLab. Cal.diy is not required. Services use real duration, local availability, blocked dates, notice, horizon and buffers. Mandatory contact fields and transactionally checked time slots replace the external iframe. Pending requests occupy time; retries are idempotent.

OWNER/ADMIN can approve, decline, reschedule and edit joining information. Existing shared SMTP notifications, reminders, calendar recipient/scope controls, CSV export and 30-day history remain. Conference links are manually configured; external calendar conflict checking and OAuth are not added. Existing provider records are preserved and remain read-only to native management.

Deploy the additive native_booking migration and update the compiled CMS plus addon package. Configure availability, organizer email and meeting details in Admin > Addons > Booking; use existing notification/reminder/retention cron jobs. No separate booking hostname or Cal.diy installation is needed.

Validation is recorded in docs/booking-contact-calendar-qa.md.

The updater now reloads the current page after an observed update finishes successfully and the new runtime answers the authenticated status check. Restart interruptions are retried without reloading into an unavailable server. Previously saved success statuses do not trigger reload loops. Native booking origin validation uses the browser-facing Host and forwarded protocol, preserving cross-origin rejection behind Next.js internal URL rewriting and TLS proxies.

Admin reservation screens are now labelled Appointments, with a direct navigation shortcut below Dashboard in desktop and mobile menus. The shortcut inherits active-addon and OWNER/ADMIN visibility from the existing navigation permissions.
